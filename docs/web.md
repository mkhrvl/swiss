# Web conventions

For a map of the current system, see [the architecture overview](../ARCHITECTURE.md). This guide covers implementation conventions.

The pnpm workspace has two independently presented hosts: `apps/pwa` uses React/Vite/PWA and `apps/extension` uses React/WXT. `packages/core` is the private `@swiss/core` package. Keep processing in feature-local core modules and expose feature subpaths; hosts compile TypeScript source directly. Core can use browser APIs, but must not import React, WXT, host storage, or extension APIs.

Use strict TypeScript and named exports. Expected validation failures return `Result<T, FeatureError>`; unexpected failures throw. Hosts own error wording. Keep tests beside the feature implementation and test observable contracts. Keep browser tests under their host's `tests/browser/`. Shared browser test support lives in `scripts/`, without production test hooks.

Hosts own screens, layouts, clipboard integration, downloads, caches, and workspace state. `packages/ui` exposes shared shadcn/ui primitives at `@swiss/ui/components/*` and shared theme tokens at `@swiss/ui/styles.css`. Both hosts compile its React/TypeScript source directly. Keep this package independent of core, tool state, WXT, and platform integrations. Feature components remain host-local; compose the primitives independently for each host. Keep tool state above routed feature screens so navigation preserves inputs and jobs. Persist offline assets and preferences only; no inputs, images, results, or job payloads in storage, URLs, logs, or remote requests. Input-transfer URLs contain only an expiring opaque token, consumed once from background memory.

Core's OCR manifest pins Tesseract.js/core 7.0.0 and English model package 1.0.0, with the model sizes and SHA-256 values for gzip and decoded bytes. Servers such as Vite label the model with `Content-Encoding: gzip`, so Fetch supplies decoded data; both representations are checked against the pinned model. `scripts/prepare-web-assets.mjs` copies worker and three LSTM core variants into both hosts and English model data into both hosts. These generated assets are ignored and rebuilt from the lockfile. Extension executables and model data are always bundled locally, without download permissions. Hosts load assets lazily as part of recognition; the PWA caches first-use assets and replaces missing or damaged model data automatically.

`patches/tesseract.js@7.0.0.patch` fixes the upstream initializer's use of `Lang.data` instead of `Lang.code`, in source and the packaged worker. Without it, supplied model bytes become a language filename. Keep the patch in pnpm's lockfile. Verify supplied-model recognition in all supported browsers before changing this dependency or removing the patch. The bundled worker/core retain their Apache-2.0 notices; the English model package is MIT licensed.

OCR runs in a processing worker, which owns image decoding, region validation, cropping, model integrity verification, and its nested Tesseract worker. Only one job per engine may run. Cancellation/disposal terminates the processing worker and its descendants. Vite bundles a module-worker entry for the PWA. WXT bundles an unlisted `ocr-worker.js` for the extension, including development, so its worker always starts from the extension origin. The Firefox CSP is authored as an object for WXT to add development sources before converting it to Manifest V2. Hosts suppress stale progress/results when an image is replaced. Asset loading and engine initialization happen lazily within the same cancellable recognition action.

Use semantic HTML, explicit labels, visible keyboard focus, and read-only text areas for selectable results. Use native `<output>` elements for live status feedback rather than adding `role="status"` to generic elements. Extract multi-step conditions into independent statements instead of nesting ternaries in JSX. Crop coordinates also have numeric inputs so selection does not require dragging. Check 320px extension sidebars, 360px web screens, desktop widths, and long content. Copy uses a user gesture and reports clipboard failure. PWA updates require a deliberate reload; do not automatically discard workspace state.

Run `pnpm verify` for formatting, lint, types, core tests and production builds. Run `pnpm test:browser` for Chromium. Use the stock-browser BiDi runner in [the development guide](development.md) for Firefox and Zen. `pnpm test:dev` checks OCR against cold-start Vite; `SWISS_GECKO=/path/to/firefox pnpm test:dev:firefox` checks the live WXT build. Prebundle the nested Tesseract dependency to prevent its first use from causing a Vite page reload. Test real OCR, cropping, cancellation/restart, state lifetime, input transfer, and offline behavior. Native browser chrome and permission prompts require interactive checks before release.

`eslint.config.mjs` checks authored TypeScript/JavaScript, React Hooks and JSX accessibility, including shared UI and browser runners. Generated assets, build outputs and agent tooling are excluded. Prettier owns formatting; TypeScript checking remains a separate command. Prefix intentionally unused callback parameters with `_`; keep rule suppressions local and explain their purpose. See [code-quality checks](code-quality.md) for TypeScript compiler compatibility and optional SonarQube analysis.

Identity's business library, browser interop executable, and native tests live in `packages/core/src/identity-passwords/dotnet/`. The TypeScript bridge exposes hashing, verification outcomes, and stable errors at `@swiss/core/identity-passwords`. It creates one lazy module worker per workspace, waits for .NET readiness, and bounds concurrency. Cancellation/disposal terminates the synchronous hasher and runtime; a later operation starts fresh. Hosts own generation controls, 250 ms automatic verification, visible password inputs, stale-result suppression, and in-memory state.

`scripts/prepare-identity-assets.mjs` publishes the pinned .NET 10.0.2 runtime with SDK 10.0.112/workload 10.0.102 and Identity 10.0.12, copies raw runtime/assembly/globalization assets and the feature's worker into both hosts, and emits an asset manifest with SHA-256 checksums. The worker is a copied ES module so .NET retains its relative import URLs in Vite, WXT, production, and development. Extension executables stay on the extension origin. The PWA loads and verifies runtime files into a versioned CacheStorage cache on the first hash or automatic verification; its service worker serves them offline. Each new workspace verifies cached files and replaces missing or damaged files. Repair requests bypass service-worker caching. Loading shares the operation’s cancellation signal and busy state. Bump the asset version whenever runtime or bridge contracts change; the PWA cache name follows the core manifest automatically.

`pnpm verify:identity` owns C# formatting and the 22 native Identity tests; `pnpm verify` includes it. `sh scripts/verify.sh` checks the shared C# solution with warnings treated as errors and runs the native Identity tests. Native tests use xUnit v3 on Microsoft Testing Platform and AwesomeAssertions for assertions. The shared browser checks exercise real C#/WASM hashing, native-generated V2/V3 fixtures, independent salts, exact passwords, cancellation/restart, latest-input results, navigation state, clearing/visible passwords, and offline reloads in both hosts. Synthetic interoperability fixtures live under `packages/core/tests/browser/`; browser-generated hash evidence stays under ignored `artifacts/web-browser/`. Live PWA and WXT development checks include Identity as well as OCR. Run asset/build commands before development browser checks; rewriting assets while WXT is running can trigger a reload during a test.

## UI components

`packages/ui/src/components/` contains shadcn/ui's New York primitives, including Sidebar, Sheet, Tooltip, Field, Card, Alert, Empty, Progress, Separator, and the input controls, with the MIT notice in `packages/ui/LICENSE.md`. Components use Radix primitives where needed and Base UI for the editable Combobox. Both libraries are MIT licensed. Styling uses the local `cn` helper (clsx and tailwind-merge). There is no shadcn runtime service. UI dependencies and assets are bundled locally for CSP and offline operation.

Both hosts use Tailwind CSS v4 through `@tailwindcss/vite`. Shared CSS owns the semantic dark theme; each host imports it and declares an explicit `@source` for its own screens. Shared component sources are scanned from the UI stylesheet. Host CSS owns page sizing, responsive layout, and OCR crop geometry. Keep component appearance in the shared theme and use component variants and slots rather than restyling native controls or overriding primitive styles. Both hosts compose SidebarProvider, Sidebar, and SidebarInset, with icon collapse on desktop and a Sheet drawer on narrow screens. Form fields use FieldGroup, Field, and FieldLabel; panels use Card slots, notices use Alert, and OCR uses Empty and Progress. Sidebar state stays in memory: the copied primitive omits upstream cookie persistence and restores focus to its external trigger when the mobile Sheet closes. The trigger exposes expanded state; shared animation styles are bundled locally. Use orientation-specific sizing utilities when adapting Separators so their default full width/height does not override inset sizing. The shared stylesheet respects `prefers-reduced-motion: reduce` by disabling animations, transitions, and smooth scrolling in both hosts. Preserve labels, read-only outputs, keyboard focus, disabled states, and visible password inputs when composing primitives.

The pinned CLI and each workspace's `components.json` support adding primitives to the UI package from either host:

```sh
pnpm exec shadcn add <component> --cwd apps/pwa
```

Both host configurations point `ui` and `utils` at `@swiss/ui`; the UI package uses local package imports. Inspect generated source and dependency changes before accepting component updates, and preserve Swiss theme/layout adaptations. Add only components needed by a screen. Business logic remains in `@swiss/core`.

The official shadcn skill is installed for Codex under `.agents/skills/shadcn/`, with its source recorded in `skills-lock.json`. The unsupported upstream `user-invocable` metadata field is omitted for compatibility with Codex's skill validator. Follow this repository's pinned CLI, shared-package aliases, and host layout conventions when applying the skill.

The repository's `.codex/config.toml` configures the official shadcn MCP server using the pinned CLI. Run `pnpm install`, then start a fresh Codex session in this trusted repository to load its tools. The server runs from `apps/pwa`, whose component aliases target the shared UI package.

The same configuration includes the official Playwright MCP server, pinned to `@playwright/mcp@0.0.83` and launched through `pnpm dlx`. It uses headless Chromium with an in-memory browser profile and writes automatically named output to the ignored `artifacts/playwright-mcp/` directory. The first launch needs network access to download the server. Install its matching browser with `pnpm dlx @playwright/mcp@0.0.83 install-browser chromium` if needed. Restart Codex to load the server; continue using the existing browser test commands for repeatable verification and stock Firefox/Zen checks.

The official NuGet MCP server is pinned to `NuGet.Mcp.Server@1.4.16` and runs from the repository root through .NET 10's `dnx`. Its first launch needs network access to download the tool from NuGet.org. It provides package metadata, compatibility and vulnerability checks, and package updates. Inspect dependency changes, including `Directory.Packages.props`, and run the relevant verification before accepting an update. Start a fresh Codex session to load its tools.

Identity and bcrypt password fields use labelled shadcn Input controls with `type="text"`, autocomplete off and spellcheck disabled. Passwords are visible in both hashing and verification, including after navigation and extension transfer. There are no reveal toggles or visibility state; Clear erases inputs and results.

## Secret generation

`@swiss/core/secret-generation` owns API token generation, JWT HMAC key sizes/encodings, and password rules. Use Web Crypto’s `getRandomValues` exclusively, with no insecure fallback. API keys accept 16–128 random bytes; JWT HS256/HS384/HS512 use 32/48/64 bytes (RFC 7518 section 3.2). Encodings are Base64url without padding, standard Base64, and lowercase Hex. These are local secret values, not provisioned service credentials or signed JWTs.

Passwords accept 8–128 characters and selected lowercase/uppercase/digit/symbol groups. Rejection sampling removes modulo bias; whole candidates are rejected until every selected group appears, so valid passwords are sampled uniformly. Deduplicate character types. Core validation failures return feature errors; hosts own wording and presentation. No assets, runtime initialization, worker, or third-party crypto dependency is needed for these bounded operations.

Host workspace state owns independent options, visible results, copy feedback, and result invalidation. On first opening, each generator automatically creates five results using its current options. Track the option snapshot used for generation in workspace state so navigation, unrelated rerenders and effect replay preserve results and errors. Generate replaces all five results; inline regeneration replaces only its row. Every option change invalidates old results and clipboard feedback, then automatically generates all five results with the latest settings. Invalid settings leave empty results and a validation message. Generators have no Clear action. Never persist or log secrets. Extension transfers copy only generator options, never results; the receiving workspace generates fresh results using the transferred options. Compose shadcn Field, Input Group, Checkbox and Toggle Group controls. Random bytes use an editable Combobox with 16–128 presets in steps of 16, retaining custom whole-number values within the same bounds. Password length uses a labelled Slider thumb alongside a synchronized numeric input (8–128). Generated-value fields use a trailing Lucide regenerate icon and COPY text button with accessible row labels. Successful copies show COPIED for two seconds. Per-row versions suppress stale clipboard feedback; timers are cancelled on replacement, clearing and disposal. Show “All tools run locally.” once in each sidebar footer. Core tests cover cryptographic encodings, HMAC key interoperability, bounds, selected character groups, unbiased sampling and failure without insecure fallback. Shared browser checks cover controls, navigation/state, visible results/copy feedback, automatic option regeneration, validation, narrow layouts and offline reloads in both hosts.

## Bcrypt passwords

`@swiss/core/bcrypt-passwords` owns cost bounds/ratings, password byte validation, hash inspection and the cancellable worker engine. bcryptjs 3.0.3 runs synchronous processing inside a dedicated worker. Generation uses a 16-byte Web Crypto salt, emits `$2b$`, supports costs 4–20 and defaults to 12. Asset preparation copies bcryptjs’s BSD-3-Clause notice to `public/licenses/bcryptjs.txt` in both hosts and their distributions. Verification accepts `$2a$`, `$2b$`, `$2y$` with embedded costs 4–20; reject malformed hashes and higher costs before creating a worker. Reject passwords over 72 UTF-8 bytes in both operations instead of silently truncating. Preserve exact password spaces/Unicode and never use an insecure random fallback.

The PWA bundles a module-worker entry and prebundles the nested bcryptjs dependency to prevent a first-use Vite reload; WXT bundles `bcrypt-worker.js` as an unlisted script on the extension origin in development and production. Workers start on demand, reuse after success, terminate on cancellation/disposal, and restart for later operations. One job may run per workspace. Hosts own separate hash/verify fields, visible password inputs, explicit Generate/Verify actions, cost guidance, inline copy feedback, cancellation and stale-result suppression. Input/cost edits cancel that tool's job and invalidate its result. Workspace navigation retains state; nothing is persisted or logged. PWA updates are disabled during bcrypt jobs. Extension transfer includes only password/hash inputs and the chosen cost, never results.

Core tests include independently generated Python bcrypt fixtures, salt uniqueness, exact passwords, UTF-8 bounds, cost guidance and engine cancellation/recovery. `scripts/bcrypt-browser-checks.mjs` exercises real workers in both hosts, including cost-20 cancellation, invalid input, navigation/visible passwords, offline reloads and restart. Chromium extension checks cover input-only transfers.

## JSON

`@swiss/core/json` owns strict validation, lossless token rendering and input/depth/output bounds. Microsoft’s MIT-licensed jsonc-parser 3.3.1 supplies the scanner and validation visitor. Configure it to reject comments, trailing commas, and empty content; inspect parser errors before exposing a document. Never serialize parsed JSON values for formatting: that would round large numbers and discard duplicate properties. Source token slices preserve all value literals and property order. Limit input to 262,144 UTF-16 characters, preflight nesting to 128 before recursive parsing, and cap rendered output at 2,097,152 characters before joining its pieces.

Hosts own live memoized processing, indentation/output controls, accessible validation feedback, error selection and clipboard actions. Navigation preserves source/options in the workspace provider. Copy feedback expires after two seconds; suppress stale clipboard completions when a value changes or its screen is disposed. Extension transfer carries source/options only. The parser is bundled for offline use, with its MIT notice copied into both distributions at `licenses/jsonc-parser.txt`. Core tests cover strict syntax, scalar values, literal preservation, bounded processing, errors. Shared browser checks cover live output, options, line numbering, copy success/failure, navigation, narrow layouts and offline reloads in both hosts.

JSON highlighting reuses the core scanner on incomplete input and returns token ranges, without parsing/serializing values. Bound highlighting to 2,097,152 characters and 20,000 spans, falling back to plain text beyond either limit. Shared UI renders escaped React text in an aria-hidden decorative layer; native text areas retain focus, selection, labels and values. Match font, wrapping, padding and tab geometry between both layers. Forced-colors mode hides decoration and restores native text. COPY floats over output without reserving horizontal text space.

JSON uses the full host content width, expanding when the sidebar collapses. Hosts compose shadcn Resizable panels with a keyboard-accessible divider and 240px minimum widths when the content area is at least 672px wide; narrower workspaces use stacked fields. A ResizeObserver tracks the actual content width so sidebar changes also update this layout. Its decorative layer numbers logical lines while letting soft-wrapped lines grow naturally; native controls and highlight layers share the same gutter padding. Cursor-path state and APIs are removed. Decorative line numbering is bounded to the first 20,000 logical lines; remaining content stays visible in the native control and decorative text layer.
